# 07/08 调查与交易落地记录

本轮实现依据为07、08两份设计稿。原剧本正文、NPC角色圣经和原有角色数据保持原文。以下记录运行时交互的衔接、接口和验收证据，含路线剧透。

## 已接通的体验

- 苏醒演出可跳过，失忆任务在22:17登记一次，听到港口汽笛后新增离港任务。任务簿保留本幕证据及未解的木箱、记忆真相。
- 住宅为卧室、客厅、厨房、门厅四区域。区域切换零游戏分钟，调查、拾取按原行动费用结算。水果刀与晚餐位于厨房，灯、信、收据位于客厅。
- 地点中先点区域、人物或物件，再显示当前操作。住宅区域直接切换。地区地图展示当前位置和可用连接，出发前确认耗时，结果保存后播放约一秒的可跳过步行剪影。开启声音后附带合成脚步声。
- 旁白无边框叠字，全文显示后五秒翻页。第一次点击补全逐字动画，再点击翻页。空格、回车可用，拖动不连续翻页，阅读设置和后台切换暂停计时。晋升卡等待主动确认。
- 原始事实和R01–R17推理可点击详情。组合替换输入卡，结果继承全部来源、事实和推理过程，详情支持继续推演。单纯失败不扣时间、理智或卡片。
- 特殊话题依事实或推理开放。原始收据与组合后的记录都可出示，原始收据仅谈纸面内容。已有运输记忆时，格尔曼追问才恢复地下储藏室细节并登记来源。
- 船员的引荐暗示、船长的要求与行踪消息、高价安置的费用依据和实际报价分别取得。引荐8，借火2，高价安置120，初始金钱24。
- 游戏原创港边收货人提供旧物收购与消息副本交易。物品交出后不再持有，买回价格高于收购价。消息按尚未出售的原始事实计价，卡片与知识保留。
- 手提灯持有、照明、危险路段警觉分别保存。不能在夜路凭空重燃；重燃恢复照明，不能刷新同一路段十分钟掩护。
- 取得线索、组合、实际属性差值和金钱变化显示轻提示，并保留行动记录。晋升插画展示墙内封存特性异常吸收，卡片读取实际体力、失控和技能。

## 与原设计的衔接

格尔曼负信任永久拒谈遵循项目负责人此前明确要求。07中分级修复关系的建议未采纳。告别仅结束当次会面，新证据仍可在01:10前带回，已经兑现的证据组不会再次奖励。

可售空箱是厨房工作台下独立的旧包装箱，占两格，不是床下储物箱。未定义床下箱中内容、失忆真正原因或信件收件人。怀表仍保留后续支线用途，没有新增擅自出售受托物的分支。

## 数据与公开接口

仍使用 `createGame(scenes, items)`。`items.clues`登记事实、类型、正文、设计ID与首次情报售价，`items.recipes`登记稳定配方ID、事实集合、先前推理与结果正文。`scenes.home_regions`登记区域，行动的 `region` 和 `object` 描述区域与调查对象。

知识条件 `clue`、`clue_any` 从活跃卡承载的事实判断。新增 `deduction`、`money_gte`、`lamp_lit`、`fire_here`、`item_at`、`boarding_valid`、`signal_ready`。新增效果 `add_money`、`set_lamp`、`record_fire`。条件和引用由数据校验器检查。

引擎增加以下操作。它们返回新的状态或在条件不满足时返回 `null`，继续由既有 `commitRun` 检查角色与递增回合、在浏览器锁内一次保存。

| 接口 | 行为 |
|---|---|
| `moveRoom(state, area)` | 房内零分钟切换，保留位置和回访记录 |
| `retrieve(state, item)` | 在实际放置地点取回物品，校验安全与容量 |
| `combine(state, cardIds)` | 两卡关联或同卡继续推演，保留来源与唯一奖励记录 |
| `hasFact(state, fact)` | 当前活跃卡是否承载这条原始事实 |
| `quote(state, kind, id)` | 取得当前有效交易报价，包含实际未售事实、价格、耗时 |
| `trade(state, kind, id)` | 复查并结算消息副本、实体出售或买回 |
| `acknowledge(state)` | 确认已提交的苏醒或晋升结果，不重复发放属性 |

交易使用和剧情相同的时间推进、世界事件及失败处理。整理与取放是零分钟操作。演出不发奖励，连续点击、刷新、跨标签页的旧快照不能覆盖新结果或恢复已封存角色。

## 高价路线实跑

`tests/investigation.test.mjs` 的完整筹资用例从普通人新角色开始，未直接修改金钱、时间或信任。

1. 在家取得收据、信、运输记忆、窗外目击、床下擦痕，隔门交谈，带走备用外套。经小巷出门。
2. 去码头观察船员，组合R14，支付8完成引荐。取得船长要求、行踪与船期。观察安置开销，组合R15，询问实际120报价。
3. 去货棚观察收旧物与买消息，出售外套12，以及收据25、信15、运输记忆10、床下擦痕5、窗外异常10、邻居记录10，共87。
4. 隔门调查电报局的回答、人影和染血纸，再到教堂侧门记录车辙。四条独立事实再出售20。
5. 初始24 − 引荐8 + 首批87 + 第二批20 = 123。筹资结束为1月10日01:31。
6. 返回码头，通过筛查，等到05:00。用三分钟支付120完成申请，05:03获得许可，剩余3。处理玛蕾娜请求，十分钟登船，05:13结局A。

引擎相对时间为403开始交涉、406批准、416完成登船。另有两种担保证据组合、05:50开始/06:00完成边界与猎人B线回归。付费请求不足120、筛查未通过、05:30前不能完成、许可因欺骗撤销时均不能成交。

## 公开发布的图片传输调整

首次公网验收中，住宅插画在等待时限内未加载完成。请求路径与 HTTP 200 正常，但原图单张约 2–3 MB，当前连接读取 64 KiB 约需三秒，不能沿用本地下载速度判断公开站点体验。

20 张运行时图片改用同名 WebP，总计从 47,416,811 字节缩减为 2,559,430 字节；PNG 原始文件保持不变。转换后的最长边为 1280 像素，透明通道逐像素核对保留。资源路径集中更新在 `data/assets.json`，界面和剧情无需分支处理。

本机 Python 对 WebP 的默认 MIME 识别返回 `application/octet-stream`，因此在既有静态服务映射中明确登记 `image/webp`。启动测试同时检查仓库子路径、Content-Type 和 RIFF/WEBP 文件签名，避免只检查 HTTP 200。

发布后仍需检查最终 Pages 提交与真实公网交互。公网验收和本地验收分别记录，不能以本地通过替代图片实际加载、console 与 HTTP 错误检查。
