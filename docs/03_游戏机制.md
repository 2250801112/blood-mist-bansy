# 核心游戏机制 v0.1

## 1. 时间系统

- 游戏起点：1350-01-09 22:17（本项目临时时间设定）。
- 内部以整数 `elapsed_minutes` 保存，相对起点为0；画面通过起点 + elapsed_minutes 显示日期时间。
- 调查一般消耗3-15分钟；对话一般2-5分钟；跨区域转移消耗5-20分钟（由事件定义）。
- 若玩家还未行动就跨越事件时刻，定时事件仍独立执行；不要让历史事件因为玩家没打开地图而暂停。
- **倒计时不是实时等待**：首版用“选择引起的游戏内时间推进”，不强迫用户现实中等待72小时。

| 事件 | 游戏时间 | 相对分钟 |
|---|---|---:|
| 敲门 | 1月9日 22:35 | 18 |
| 格尔曼在餐厅 | 1月10日 00:20–01:10 | 123–173 |
| 厨房争吵、堂娜救援 | 1月10日 00:25–01:05 | 128–168 |

| 港务记录原件可查 | 1月10日 10:00–12:00 | 703–823 |
| 灯塔潮汐调查 | 1月10日 16:00–18:00 | 1063–1183 |

| 班西毁灭 | 1月12日 22:17 | 4320 |

调查取灯、读信、拓录收据各耗时 5 分钟，储物箱 8 分钟，细看窗外 4 分钟。22:35 仍在房内会被敲门打断，未完成的行动不发放收益。已经离家的玩家在街上听见远处的叩击。之后继续搜查需花 3 分钟，并失去 3 理智。访客尚在时翻找木箱或取刀会引起注意，再次把玩家带到门前。

格尔曼的首次接触占用 15 分钟。完整问答最长再用 15 分钟，始终受 01:10 的截止限制。处理厨房争吵耗时 25 分钟，完成堂娜救援耗时 20 分钟。两件事同在 01:05 截止，无法在一轮全部完成。放弃或错过救援后由其他旅客处理。

登船手续耗时 10 分钟。05:50 开始且恰在 06:00 完成时，先结算登船成功，再记录离港。05:59 已来不及开始手续。筛查、最后交涉、处理玛蕾娜请求和登船是不同步骤。

## 2. 携带物品和线索

- 物品栏只有2格，灯笼、刀、信号布、外套、毯子和铜杯占1格，厨房空包装箱占2格。钱包和线索不占格。
- `clues` 为线索簿，记录读过或验证过的证据，**不占格**。例如未寄出信/收据读取后记入线索簿。
- 线索“记录”并不等于凭空持有原件；如某次交涉要求展示原件，运行时应先检查是否取到、仍能返回房间，或者将其定义为已携带的薄纸档案。第一幕首版将收据视作“已拓录可出示”线索，避免无谓格数负担。
- 玩家可以在安全地点交换携带道具；战斗/危险追逐期间禁止整理背包。

## 3. 灯笼

- 在住宅客厅发现，需要先在实际火源处点燃。厨房余火免费；餐厅和码头值夜人报价后可以支付2、用时2分钟借火。
- 危险路段首次举起已点燃的灯，开启最长 10 分钟的 `light_safety_until`，从使用完成起算。逾时后无头异变者会向藏身点靠近，改走更远的小巷仍可脱身。
- `light_alert_by_area` 保存该路段的警觉与保护截止时刻。切图和读档不重置警觉，也不能再次获得同一段保护。
- 道路上若无灯/无替代掩护，第一夜危险度显著升高；提示必须明确，不能仅暗箱判死。
- 光源不是针对第一夜电报局的免死金牌，强闯仍然死亡。

## 4. 生存属性

| 属性 | 起始 | 用途 |
|---|---:|---|
| vitality | 1 | 首版用“致命攻击即死”的生命逻辑，非血条 |
| stamina | 4 | 长途奔跑、游泳、生存判定 |
| sanity | 100 | 神秘暴露的心理压力；低值出现不可靠文本/错误判断 |
| loss_of_control | 0 | 常人初始0；非凡觉醒后累积；100进入失控结局F |
| gehrman_trust | 0 | 获取白玛瑙号担保资格，范围-100到100 |

- 观察异常事物可能使理智下降；不应任意扣理智，重要损失必须由明确事件触发。
- 成为猎人：`pathway = red_priest`，`sequence = 9`，`stamina_max = 7`，`stamina = 7`，`loss_of_control = max(current, 50)`，解锁 `hunter_instinct`。
- `sanity <= 0` 应触发精神崩溃处理；首版可强制撤离事件或进入失败，避免假装理智毫无影响。
- 失控度50-69：嗅觉/情绪异常；70-89：出现幻觉；90-99：危险指引和强烈冲动；100：结局F。

## 5. NPC关系

- `trust` 信任“是否敢将安全与关键行动托付给你”；`favor` 好感“是否愿意亲近/帮助你”，不是同一数值。
- 格尔曼申请担保须有 `gehrman_trust >= 60`、已核验证据、通过筛查、未拒谈、船仍在港，并在 05:00–05:30 办理。离港前还需完成 10 分钟登船。
- 可验证情报+20、教堂收据+25、协助救援+35、承认疑点+15、首次坦言+10；同一事件只能计分一次。
- 空口吹嘘信任 −15，隐瞒污染信任 −50。隐瞒后撤销筛查和登船许可，既有申请机会已经用过。
- 堂娜和玛蕾娜各有一组互斥答复。选定以后，同一轮中她们的交谈入口会消失。
- 先经船员引荐，听船长提供格尔曼行踪，才开放专属接触。首次回答互斥，独立证据话题可在时间允许时回访。证据需要留足追问时间。首次信任低于0时，永久写入 `gehrman_refused`，此后关闭私人谈话和担保请求。

## 6. 即死与死亡不可回溯

- 第一夜直接对无头行尸开门：死亡D。
- 电报局两名异变职员在场时强行进入：死亡E。
- 出海时准备不足/路线错误：海上遇难死亡结局（可作为B失败的子结局）。
- 失控度100：结局F。
- 死亡后封存本次人物状态和结局；用户可“新角色重新开始”，但不能将同一人物倒回到之前的选择点。成就/图鉴跨角色保存。
- 危险选项应提供可观察到的前兆；选择后可显示简短的死因和永久图鉴进度，不通过惩罚设计阻止玩家学习。

## 7. 游泳逃生资格

必须满足：

1. `pathway == red_priest` 且 `sequence == 9`，已经拥有猎人体力和观察能力。
2. `ship_schedule_known = true`（正确知道灰鸥号航线及接近时刻）。
3. `safe_sea_route_known = true`（猎人直觉判断安全下海点）。在 16:00–18:00 完成观潮与记录两步，结果只领取一次。
4. 下海前仍携带可用的求救信号（信号布，或实际持有且点燃的黄铜手提灯）。组合出的准备方案不能代替实物。
5. 时间处于1月11日04:20-04:40，体力足够，失控度小于100。

资格不足时允许尝试，但应提供不同失败文本，并给出可知晓的缺失风险；不是无信息随机判定。

## 8. 非凡成长框架（长期）

- 22条途径作为 `pathway_catalog` 的可扩展设计，不在首版实现全部效果。
- 序列4以前：每晋升一级解锁一个最有代表性的能力，其余改为被动属性修正，以减轻平衡与UI压力。
- 非凡魔药以“材料/配方线索 + 仪式要求 + 风险校验”抽象，不需要所有原作材料的详细模拟。
- 战斗未来使用回合制技能指令，支持技能额外行动、回合延缓和代价；第一幕里对不可战胜的强敌不设置虚假的战斗按钮。
- 封印物使用必须体现代价、持有条件与风险；不应直接作为普通装备加成。

## 9. 场景数据解释约定

`data/scenes.json` 的 `nodes` 每个包含 `id`、`location`、`text`、`choices`。每个选项可包含：

- `next`：下一个节点ID。
- `minutes`：游戏时间消耗。
- `requires`：一组条件，支持 `flag_true`、`flag_false`、`clue`、`item`、`stat_gte`、`stat_lt`、`minute_lt`、`minute_gte`、`minute_lte`、`pathway`、`inventory_space`、`clue_any`、`stat_lte`。
- `effects`：副作用列表，支持 `set_flag`、`add_clue`、`add_item`、`remove_item`、`add_stat`、`set_stat`、`unlock_achievement`、`unlock_skill`、`end`、`advance_to_minute`、`set_stat_min`。
- `once` 等同 `max_uses: 1`。已用满次数、被永久锁定或与既有答复互斥的选项会隐藏。
- `id`：选项在当前节点内的稳定 ID，与场景 ID 一起记录一次性行动。
- `fallback`：锁定选项的说明。需要隐藏选项时使用 `visible_when`。用 `alternative_to` 将同一动作的两个分支配对，优先显示可用的主选项，主选项锁定时显示可用的替代选项。
- `map`：在当前场景的节点地图中显示该选项。`feedback` 提供行动结果。
- `exclusive_group` 记录已选的场景与选项。用 `exclusive_open` 控制该组的交谈入口。
- `available_from` 检查行动开始，`available_until` 检查行动完成。完成时刻取直接用时与 `advance_to_minute` 的较晚值。需完成追问的入口预留追问的时间。
- `permanent_lock` 引用旗标。`dialogue_windows` 供界面显示固定世界时钟上的谈话截止点。
- `scheduled_events` 以稳定 ID 记录触发。任务结算用 `resolve_event` 写入完成、错过或由他人处理，`event_pending` 控制是否仍可领取。

运行时先校验合法性和完成时刻，再顺序触发跨越的事件。打断时只提交已经发生的世界事件及已耗时间。正常完成时，行动次数、互斥组、事件结果、收益与新场景一次写入。显式标记 `finish_before_events` 的登船操作优先于同刻离港。节点按 `redirects`、`variants` 与世界旗标切换，进入新节点时执行 `on_enter`。

港务记录过期后的高代价替代渠道留待剧情确认。当前 A 线可走证据核验组合，也可通过救援加证据达标。B 线须按原件与潮汐窗口行动。

本数据层是**可交给Codex扩展的原型模型**，最终可根据实现技术升级类型系统、事务处理和自动事件调度。
